# 🗺️ מפת ישראל — משחק ניחוש מיקומים

משחק קבוצתי בזמן אמת שבו המשתתפים מקבלים שם של עיר או אתר בישראל,
מסמנים נקודה על מפה נקייה — וצוברים נקודות לפי המרחק מהמיקום האמיתי.

המנהל פותח משחק ומקרין את הקוד; המשתתפים סורקים QR מהטלפון ומצטרפים
תוך שניות, בלי התקנה ובלי הרשמה.

## מה יש במשחק

### מסך המנהל

| יכולת | פירוט |
| --- | --- |
| יצירת משחק | קוד ייחודי בן 5 תווים, קישור הצטרפות ו-QR — כולם נוצרים מיד |
| לובי חי | רשימת המשתתפים ומספרם מתעדכנים בזמן אמת |
| שליטה מלאה | התחלה, עצירה זמנית וחידוש מדויק, דילוג לשאלה הבאה, סיום מוקדם |
| מסך משחק | שם המקום, מספר הסיבוב, טיימר, מד "כמה כבר סימנו", ניקוד מצטבר |
| סיכום | סקירת כל סיבוב על המפה, טבלת דירוג מלאה, פודיום עם קונפטי |
| ייצוא | CSV (נפתח ב-Excel), JSON, ושיתוף סיכום טקסטואלי |
| מצב מקרן | הגדלת כל הטיפוגרפיה בלחיצה אחת, לקריאה מרחוק |

### חוויית המשתתף

1. סריקת QR או כניסה לקישור.
2. הזנת שם ולחיצה על "הצטרפות למשחק".
3. מסך המתנה עד שהמנהל מתחיל.
4. בכל סיבוב: שם המקום + טיימר, וסימון נקודה אחת על המפה.
   ניתן לגרור ולתקן עד תום הזמן — אחריו הסימון ננעל.
5. בסיום: מסך אישי עם הסימונים שלי מול המיקומים האמיתיים, הדירוג והפודיום.

### מה **לא** נחשף במהלך המשחק

זו דרישת יסוד של המשחק, והיא נאכפת בשרת ולא רק בממשק: המיקום האמיתי,
המרחקים והניחושים של שחקנים אחרים **אינם נשלחים כלל לדפדפן** לפני
סיום המשחק. מה שכן מוצג: ניקוד מצטבר, מספר הסיבוב והטיימר.

## הפעלה מהירה

דרישה מוקדמת: **Node.js 20.11 ומעלה**.

```bash
npm install          # התקנת כל חבילות ה-workspace
npm run build        # בניית shared → client → server
npm start            # השרת מגיש גם את הלקוח, בכתובת http://localhost:3000
```

### פיתוח

```bash
npm run dev          # שרת (3000) + Vite עם HMR (5173) במקביל
```

בפיתוח יש להיכנס ל-<http://localhost:5173>. בקשות ה-WebSocket מנותבות
אוטומטית לשרת, כך שההתנהגות זהה לייצור.

> **לשחק מהטלפון בזמן פיתוח:** שרת ה-Vite מאזין לכל הכתובות ברשת
> המקומית. היכנסו מהמחשב לכתובת ה-IP של המחשב ברשת (למשל
> `http://192.168.1.20:5173`) — ה-QR ייווצר עם אותה כתובת ויעבוד מהטלפון.

### עקרונות מנחים

**השרת הוא מקור האמת היחיד.**
הזמן, סדר השאלות, המיקומים האמיתיים והניקוד נמצאים בשרת בלבד.
הלקוח מציג — ולא מחשב. כך אין רמאות ואין מצב שבו שני מסכים
מראים דברים שונים.

**לוגיקה משותפת נכתבת פעם אחת.**
חישוב המרחק, נוסחת הניקוד, בניית הדירוג וההיטל של המפה יושבים
ב-`shared` ורצים בדיוק אותו הדבר בשני הצדדים. השרת מחשב את
הניקוד; הלקוח משתמש באותן פונקציות לייצוא ולתצוגה.

**מנוע המשחק אינו מכיר רשת.**
`GameRoom` לא יודע דבר על Socket.IO — הוא מדווח על שינויים דרך
callbacks ומקבל `Scheduler` בהזרקה. לכן הוא נבדק במלואו עם שעון
מדומה, בלי לפתוח אף חיבור.

**זמן מסונכרן, לא זמן מקומי.**
כל טיימר מבוסס על חותמות זמן של השרת. הלקוח מודד את הפרש
השעונים בשיטת Cristian עם מספר דגימות, כך שגם מכשיר עם שעון
שגוי מציג את אותה שנייה כמו כולם.

**RTL מלא, לא תוספת.**
כל ה-CSS משתמש במאפיינים לוגיים (`inline-start`/`inline-end`),
ולכן העברית עובדת נכון והוספת שפה נוספת אינה דורשת שכתוב.

### זרימת המשחק

```
lobby ──start──▶ countdown ──▶ question ──┬──▶ intermission ──▶ question …
  ▲                  │            │       │
  │                pause/resume ◀─┘       └── (שאלה אחרונה) ──▶ finished
  └──────────────── restart ─────────────────────────────────────┘
```

חיבור מחדש נתמך בכל שלב: לכל שחקן וגם למנהל יש אסימון סודי הנשמר
מקומית, ורענון דף או נפילת רשת מחזירים אותו לאותו מקום עם אותו ניקוד.

## מנגנון הניקוד

הניקוד רציף — לא בינארי — ונגזר ישירות מהמרחק בקילומטרים:

```
score(d) = 1000 · e^(−max(0, d − 1.5) / 30)
```

| מרחק | ניקוד |
| ---: | ---: |
| עד 1.5 ק״מ | 1000 |
| 5 ק״מ | 890 |
| 10 ק״מ | 754 |
| 25 ק״מ | 462 |
| 50 ק״מ | 203 |
| 100 ק״מ | 37 |

**למה אקספוננציאלי?** כדי שהפרש של 5 ק״מ בסימון מדויק "יכאב" הרבה
יותר מהפרש של 5 ק״מ בסימון גרוע ממילא. הגישה מתגמלת דיוק אמיתי,
אך לא מאפסת ניחוש בינוני — כך המשחק נשאר פתוח עד הסוף.

המרחק מחושב בנוסחת Haversine על גבי WGS84. שוברי שוויון בדירוג:
מרחק ממוצע נמוך יותר, ואז מספר "בולי פגיעה".

בונוס מהירות (עד 10%) קיים כאפשרות, אך **מכובה כברירת מחדל** —
כדי שהניקוד ייקבע אך ורק לפי דיוק גיאוגרפי.

## המפה והנתונים הגיאוגרפיים

המפה מצוירת כ-SVG וכוללת בדיוק את מה שנדרש: **גבולות המדינה, קו החוף,
הכנרת וים המלח** — ללא שמות ערים, כבישים, כיתובים או סימונים.

- **מקור הנתונים:** Natural Earth בקנה מידה 1:10m (נחלת הכלל).
- **עיבוד:** המצולעים אוחדו, פושטו באלגוריתם Douglas–Peucker ועוגלו
  ל-4 ספרות (~11 מטר) — סך הכול כ-6KB.
- **היטל:** Web Mercator, זהה לזה של Google Maps, ולכן הצורה מוכרת.
  ההיטל **הפיך במדויק**: אותה פונקציה מציירת את המפה וגם מתרגמת
  את לחיצת המשתמש בחזרה לקואורדינטות. שני הצירים באותן יחידות,
  כך שקנה המידה זהה לרוחב ולאורך (יש בדיקה שמאמתת זאת).

לדיוק במגע: בזמן נגיעה מוצגת זכוכית מגדלת מעל האצבע עם צלב כוונת,
וניתן לגרור עד לשחרור.

## תצורה

כל ההגדרות דרך משתני סביבה, עם ערכי ברירת מחדל שמתאימים להרצה מקומית.

| משתנה | ברירת מחדל | תיאור |
| --- | --- | --- |
| `PORT` | `3000` | פורט ההאזנה |
| `HOST` | `0.0.0.0` | כתובת ההאזנה |
| `PUBLIC_BASE_URL` | *(נגזר מהבקשה)* | כתובת ציבורית לבניית קישור ה-QR. הכרחי מאחורי פרוקסי שמשנה מארח |
| `CORS_ORIGINS` | `*` | מקורות מותרים, מופרדים בפסיק |
| `ROOM_TTL_MINUTES` | `240` | משך חוסר פעילות שאחריו חדר נטוש נסגר |
| `MAX_ROOMS` | `500` | תקרת חדרים פעילים בתהליך |
| `SERVE_CLIENT` | `true` | האם להגיש את קבצי הלקוח הבנויים |
| `CLIENT_DIR` | `client/dist` | נתיב לתיקיית הלקוח |
| `TRUST_PROXY` | `true` | כיבוד כותרות `X-Forwarded-*` |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |

ראו `.env.example`.

## פריסה לייצור

השרת מגיש גם את ה-API וגם את הלקוח — שירות אחד, בלי בעיות CORS
ובלי תלות ב-CDN.

```bash
npm ci
npm run build
NODE_ENV=production PORT=3000 PUBLIC_BASE_URL=https://example.com npm start
```

### Docker

```bash
docker build -t mapat-israel .
docker run -p 3000:3000 -e PUBLIC_BASE_URL=https://example.com mapat-israel
```

### הערות תפעול

- **WebSocket:** יש לוודא שהפרוקסי (nginx / ALB / Cloudflare) מעביר
  שדרוג ל-WebSocket. בהיעדרו, Socket.IO נופל אוטומטית ל-polling.
- **מכונה בודדת:** מצב המשחק נשמר בזיכרון התהליך. זו הבחירה הנכונה
  למשחק חי — אפס השהיה, אפס תלות. להרצה על כמה מכונות יש לממש את
  המנשק `RoomStore` (ב-`server/src/game/RoomRegistry.ts`) מעל Redis
  ולהוסיף `@socket.io/redis-adapter`.
- **בדיקת תקינות:** `GET /healthz` מחזיר סטטוס, זמן פעילות ומספר
  חדרים פעילים.
- **כיבוי מסודר:** `SIGTERM`/`SIGINT` סוגרים חדרים וחיבורים לפני יציאה.

### אבטחה

- כותרות אבטחה ו-CSP באמצעות Helmet.
- הגבלת קצב (token bucket) לכל חיבור ולכל סוג פעולה.
- כל קלט מהלקוח מאומת ומוגבל בשרת: שמות מנוקים מתווי בקרה ומתווי
  כיווניות בלתי נראים, קואורדינטות נבדקות מול גבולות המפה, והגדרות
  מוגבלות לטווחים מותרים.
- אסימוני מנהל ושחקן נוצרים בעזרת `crypto.randomUUID` ומושווים
  בהשוואה בזמן קבוע.
- קודי המשחק מיוצרים ב-`crypto.randomInt` — לא ניתן לנחש קוד של
  משחק פעיל.

## בדיקות

```bash
npm test
```

מכוסים:

- **לוגיקת ליבה** — מרחקים, רציפות ומונוטוניות הניקוד, בניית הדירוג,
  הפיכות ההיטל ואחידות קנה המידה, שלמות חבילת התוכן.

  בתום הזמן, הקפאה וחידוש מדויקים, סיום מוקדם, משחק חוזר, ואימות
  שהמצב הציבורי **לעולם אינו מכיל מיקום אמיתי**.

  דחיית שם כפול, חסימת פקודות מנהל משחקן, משחק מלא, חיבור מחדש,
  וסנכרון שעונים.

## הרחבת המשחק

המערכת נבנתה כך שההרחבות הבאות יהיו הוספת **נתונים**, לא שינוי קוד:

**קטגוריה חדשה** — הוסיפו רשומה ל-`shared/src/content/packs/index.ts`.
היא תופיע אוטומטית במסך יצירת המשחק.

**מפה של מדינה אחרת** — הוסיפו גיאומטריה ורשומה ב-
`shared/src/content/maps/index.ts`. רכיב המפה, ההיטל, הניקוד והשרת
אגנוסטיים למפה ויעבדו ללא שינוי.

**כלל ניקוד אחר** — `ScoringConfig` מועבר כפרמטר; אין ערכים קשיחים.

**אחסון מתמיד, היסטוריה, משתמשים, ליגות** — `RoomStore` הוא מנשק,
ו-`GameResults` הוא מבנה שלם וסגור שאפשר לשמור כמו שהוא.

**ייצוא ל-PDF** — הכנה קיימת: סגנונות הדפסה מוגדרים ב-`base.css`
ומחלקת `no-print` מסתירה בקרות, כך שהדפסת מסך התוצאות מייצרת מסמך נקי.
